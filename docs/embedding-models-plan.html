The next step is learned embeddings, but the decision is not only about text quality. We need local Windows inference, image similarity, natural-language search, and a clean path to text-to-image retrieval.

Decision brief · researched August 22, 2026 · recommendation for the first learned-model spike

Recommendation: test and provisionally adopt Nomic Embed Text v1.5 with Nomic Embed Vision v1.5. They share one embedding space, which means a text query can find images by meaning. Keep BGE small English v1.5 plus a small CLIP-style encoder as the fallback if Nomic export or CPU performance does not hold up.

Why this fits the project

The current corpus is English-first and covers articles, notes, quotes, PDFs, screenshots, OCR text, photos, moodboards, and visually similar image pairs. The app already has a persisted background job and a model boundary in Rust. The learned model should improve retrieval without changing capture or making users manage AI output.

one space Text + image retrieval

Text embeddings and image embeddings can be compared directly, so "warm interiors" can return both an article and a matching image.

768 → 128 Storage headroom

Nomic Text v1.5 supports Matryoshka-style dimensionality choices. Start at 768 for quality, then measure whether 512 or 256 is enough.

Apache 2.0 Model license

The Nomic text and vision model cards list Apache 2.0. That is easier to ship with this MIT project than a gated or research-only model.

Shortlist

The shortlist favors models that can run locally and have a believable ONNX path. Leaderboard scores are useful for narrowing the field, not for making the final decision.

Proposed behavior

01

Capture

Create the card immediately. Keep URL, file, OCR, and extracted article text as today.

02

Prepare

Build one stable text input from title, description, source, OCR, note body, and extracted content.

03

Encode

Run text and vision jobs in the existing worker. Normalize every vector and record its model revision.

04

Rank

Blend exact FTS5 hits with semantic scores. Keep image similarity as a separate visual action until the ranking feels right.

Storage shape

  • Keep the existing embedding table and model discriminator.
  • Use stable IDs such as nomic-text-v1.5 and nomic-vision-v1.5.
  • Record dimension, model revision, preprocessing version, and source content hash.
  • Store normalized float vectors first. Add quantized storage only after quality and recall are measured.
  • When an image has OCR or useful metadata, store both its vision vector and a text vector. This lets a text query find the image through either meaning or visible words.

One deliberate constraint

Start with one item-level text vector. Do not introduce chunk storage for every article and PDF yet. If long-document tests show that one vector misses useful passages, add chunk vectors as a second index with clear provenance.

Benchmark before we commit

The existing 48-item corpus is enough to expose the first failures. Add a small hand-written query set so the benchmark measures the product we want, not only generic embedding behavior.

Text retrieval

Test exact-title misses, paraphrases, OCR terms, article themes, note meaning, PDF language, and negative distractors. Compare FTS5 alone, embeddings alone, and a hybrid rank.

Visual retrieval

Query the warm interior pair, the desert pair, and the ocean distractor. Measure whether composition survives color changes and whether low-resolution images degrade gracefully.

Local runtime

Record download size, cold start, warm latency, peak RAM, CPU time per item, batch throughput, and DirectML behavior. Run on CPU first, then try GPU acceleration.

Suggested acceptance gates

  • Exact and OCR search remain available when a model is missing or a job fails.
  • The learned model beats the deterministic encoder on hand-written semantic queries without causing obvious false positives.
  • The Nomic pair returns relevant text and images for cross-modal queries, not only same-type results.
  • First-run model download is explicit, resumable, and separate from the application installer.
  • Changing the model revision marks old vectors stale and gives the worker a safe reindex path.

Implementation order

  1. Build a small model runner outside the UI and export Nomic text and vision to ONNX.
  2. Verify tokenizer, image resize, normalization, pooling, output dimensions, and cosine scores against the reference implementation.
  3. Add a model manifest with revision, license text, download URL, expected files, and SHA-256 hashes.
  4. Replace the deterministic functions behind the existing Rust boundary.
  5. Reindex the benchmark corpus, add semantic query commands, and compare hybrid ranking.
  6. Only then decide whether 768 dimensions or a smaller Matryoshka slice is the production default.

Fallback rule

If Nomic cannot meet the CPU or packaging budget, choose BGE small v1.5 for text and a compact CLIP-family image encoder for visual similarity. Keep cross-modal search as a later feature rather than forcing incompatible spaces together.

This is the safe engineering fallback, not the preferred product behavior.

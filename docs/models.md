# Local search models

## Active index

`electron/search-model-manifest.json` pins the source revision, download URL and SHA-256 of every shipped asset. The active model pair is:

- **EmbeddingGemma 2**, ONNX Community q8 export of Google's model (Apache-2.0): normalized 768-dimensional text and image embeddings. The embedding space is independent of Nomic, even though both have 768 dimensions.
- **Florence-2-base-ft**, ONNX Community q8 export of Microsoft's model (MIT): bounded detailed image captions (`<MORE_DETAILED_CAPTION>`, at most 96 generated tokens). Suggested tags are derived from captions, not an independent object detector or verified breed classifier.

Transformers.js and ONNX Runtime keep the same pinned q8 weights and float32 activations/outputs on every provider. Indexing prefers an available CUDA provider on Linux/NVIDIA, or a runtime-supported CUDA/DirectML provider on Windows, then WebGPU where exposed. Only one indexing model family is resident. A failed GPU load, inference, allocation, timeout or child-process crash retires that process and retries the identical request once on CPU; that model family stays on CPU for the session. This is graceful fallback, not a guarantee that every GPU supports these graphs. CPU uses two intra-op threads and one inter-op thread. Tesseract OCR remains CPU/WASM: its installed runtime has no CUDA provider. Text queries use `task: search result | query: ...`; document passages use `title: ... | text: ...`. Image preprocessing is supplied by the pinned model processor.

## Capture and backfill

Thumbnails stay on their own fast job lane. Images receive a visual vector before OCR. Existing library items backfill one at a time while idle; captions follow initial indexing. OCR and captions cause passage reindexing, reusing a content-hashed image vector. Long documents use overlapping passages of at most 1,800 UTF-16 code units with 180-unit overlap, preserving Unicode boundaries. PDF pages are stored separately and each passage retains its page number.

EmbeddingGemma 2 and Florence indexing run in a bounded isolated child-process queue. Typed queries use a separate text-only CPU child with identical weights/prefix, so active image/caption work cannot hold the query queue or allocate another vision model in VRAM. Processes retire on model-family changes or after 60 seconds idle; individual calls have a two-minute ceiling. The retained Nomic fallback query encoder still runs in the main process, outside this lifecycle.

The optional Linux x64 CUDA runtime is a build-time input, not a runtime download: supply `INKLING_CUDA_RUNTIME_DIR` to the packaging model-preparation step. `electron/search-accelerators.json` pins vendor distributions and every runtime/license file; `prepare-search-accelerators.mjs` verifies them and the ONNX provider before staging. Without that bundle, compatible system libraries may support CUDA; otherwise the CPU fallback remains usable. Vendor NVIDIA libraries retain their original proprietary licenses in the accelerator directory and are not covered by this repository's MIT license. Windows DirectML/CUDA and other GPU types require their own platform execution checks.

Published original-asset paths are immutable. Saving an existing item under the same filename uses exclusive-create and a fresh basename rather than overwriting bytes an in-flight decoder might own. Caption, PDF page and OCR commits are bound to that asset path. Vector/chunk commits additionally check the item's revision atomically. Background metadata does not replace user titles/tags/OCR. Removing a suggested tag is persisted as a tombstone and survives recaptioning and export/import.

## Retrieval and migration

FTS5 (or escaped LIKE fallback) handles exact names, OCR, numbers and passage text. Text and visual vectors have separate acceptance floors (0.70 text, 0.63 image for the current pinned index). Reciprocal-rank fusion combines independently ranked lanes, deduplicating items rather than comparing raw scores across model families. Smart Space kind/tag/exclusion predicates apply before lane limits. The current image lane also excludes candidates more than 0.06 cosine below its best accepted visual hit, before rank fusion; exact text matches remain independent. This margin was checked against targeted cat/dog/breed hard negatives and replayed against the frozen original corpus, not certified as a universal category boundary. Read-time scoring changes and GPU selection do not invalidate stored vectors. Changing embedding weights or preprocessing requires a new embedding index version and evaluation. The separate caption version `florence2-base-ft-q8-detailed-v2` schedules old image captions for background replacement and text re-embedding, preserving content-hashed visual vectors, user metadata, OCR and removed-tag tombstones.

New vectors, passages, page text, AI annotations and readiness state live in separate `search_*` tables. Revision fences hide stale passages/vectors while edits reindex. Caption/tag-only commits carry unchanged image-vector revisions forward atomically, keeping visual results available while their text passages rebuild. Archived items are excluded and deletion clears their indexes. Legacy Nomic vectors remain intact and are queried only with the Nomic query encoder; the old 0.55 floor is retained for that fallback. They are never compared with Gemma vectors. The previous Nomic normalization and 224px vision processor remain unchanged for this migration lane.

Queries never download models. Packaged builds bundle all pinned files; development indexing may fetch verified assets into `<library>/models/search/<repo>`. Missing/broken models produce an explicit visual-search-unavailable notice while exact text search continues. `get_search_progress` reports ready and total active items; the library shows indexing progress.

## Validation boundaries

Linux CPU inference and source storage have local regression evidence. Public IPC, the built interface, packaged resources and the local preview installer are separate verification gates; a source review alone does not establish their completion. A small independently labeled image corpus and synthetic PDF fixtures provide regression evidence, not general accuracy certification. Public photos can overlap model pretraining; PDF calibration and held-out query phrasings share the same three synthetic documents. Quantized parity is measured against the matching float32 ONNX export, not official PyTorch inference. Windows runtime and installer execution still require a Windows machine.

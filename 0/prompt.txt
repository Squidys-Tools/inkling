## How to fix (behavior must not change)
- set-state-in-effect: derive the value during render, reset state with a `key`, or move the update into the event handler that causes it. If the effect truly synchronizes with something outside React and a synchronous setState is required (e.g. measuring layout, subscribing to a store/observer, a one-time mount read from an external API), keep it and add `// oxlint-disable-next-line react/set-state-in-effect -- <specific reason>`; the reason must say what external thing it syncs. Prefer a real fix; use disables sparingly and justify each.
- refs: do not read or write `ref.current` during render. Typical fixes: keep the latest-callback ref updates inside an effect or layout effect, or use state/derived value. Event handlers and effects may use refs.
- immutability (src/components/LiquidGlass.tsx ~line 433): do not mutate a value from useState or reassign locals after render.
- exhaustive-effect-dependencies: remove the extra dependencies, but double check the effect really should not re-run on them.
- Hot paths matter: the library grid, card, item overlay, and mascot are performance-sensitive. Do not add renders, re-subscriptions, or work per scroll/frame. No continuously repainting animations. Do not change the mascot's timing/behavior.
- Do not add comments restating code. Keep diffs small per file; no refactors beyond what each fix needs.
- Remove the `"off"` lines for these rules in `.oxlintrc.json` and set all five to `"error"` (`react/refs`, `react/set-state-in-effect`, `react/exhaustive-effect-dependencies`, `react/immutability`, `react/purity`). Leave other rules as they are. Check the overrides section still makes sense.

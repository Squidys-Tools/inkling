## Goal
Add `bun run check:changed`: one command an agent or dev runs while iterating and before pushing. It runs the fast subset of CI's checks for only what the branch changed. `bun run check` (the full CI mirror) stays as is. Inspiration is t3code's `scripts/check-changed.ts` (https://github.com/pingdotgg/t3code/blob/main/scripts/check-changed.ts), but ours must be much smaller: yagni, aim for roughly 100 lines. Do NOT copy its run-result cache, workspace/affected-package mapping, patch check, or GraphQL parts.

## Behavior
- `bun run check:changed` compares against `git merge-base HEAD origin/main`; optional first argument is another ref. If there is no merge base, print a one-line hint to `git fetch origin` and exit 1.
- Changed files = `git diff --name-only --no-renames <base>` plus untracked files (`git ls-files --others --exclude-standard`). Only files that still exist are passed to tools. No changes -> print so and exit 0.
- Steps (run concurrently, print each step's output when it finishes, then a pass/fail summary, exit non-zero if any failed):
  1. `oxlint` on changed JS/TS files (`bunx oxlint <files>` or the local binary; match how package.json's `lint` script invokes it).
  2. `oxfmt --check` on changed files oxfmt handles. Make sure files in `.oxfmtrc.json` ignorePatterns (md, yml, bun.lock, etc.) are not passed in a way that makes oxfmt error with "no target files"; test this with a docs-only change and with an ignored file.
  3. `bun test` on changed test files plus sibling tests of changed source files (`foo.ts` -> `foo.test.ts` in the same directory; also `.test.tsx`). Skip the step when none.
  4. `bun run knip` when any code file or package.json/knip.json changed.
  5. `bun run typecheck` when any code or tsconfig/package.json changed (it is fast enough to run whole).
- Must work on Windows (backslash paths from git are forward-slash; normalize anyway) and in a git worktree.
